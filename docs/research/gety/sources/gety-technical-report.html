01 / Overview

Executive summary

Gety is a local-first search application that indexes documents and exposes a searchable corpus to both desktop users and external AI applications. It is a retrieval system, not a generative assistant: answer synthesis is delegated to the connected AI tool. The product separates content ingestion, local search and downstream reasoning, allowing several tools to use the same index.

384Embedding dimensions
3Supported desktop OS families
3Primary integration interfaces: MCP, API, CLI

Core capabilities include lexical and semantic search, OCR, previews, background indexing, custom data connectors and controlled disclosure of search results. The published embedding model is MIT-licensed; that license does not establish that the application itself is open source.

03 / Ingestion

Indexing lifecycle

Indexing is progressive: title discovery precedes more expensive extraction, OCR and neural embedding work. Results become available as individual stages complete. After initial ingestion, filesystem changes trigger incremental updates for additions, modifications and deletions.

Resource scheduling

Automatic mode adapts processing to machine load and power conditions. Full-speed mode favors indexing throughput; pause mode suspends background work while keeping existing results usable. Indexing duration depends on corpus composition, OCR burden and hardware.

Storage lifecycle

The local data directory separates search/index storage from AI models and dependencies. The application provides storage optimization and managed migration to another disk. Preserving the data directory can avoid reindexing after reinstalling; the index is not intended to be transplanted directly to another machine.

05 / Neural components

AI models and inference

gety-embed-v0

The published multilingual sentence encoder is fine-tuned from multilingual-e5-small using public and proprietary synthetic training material tailored to local search. Its base is approximately 118 million parameters; outputs have 384 dimensions, with a sequence capacity of 512 tokens. The Gety model card identifies an MIT license.

ExportPrecisionSize
onnx/model_uint8.onnxDynamic UINT8112 MB
onnx_cuda/model_fp16.onnxFP16224 MB
coreml/model_fp16.mlpackageFP16224 MB
openvino/model.xml + model.binINT8 weights, FP16 activations114 MB

The accelerated exports integrate pooling and normalization into their graphs. The Core ML export accepts an unpadded variable-length sequence. OpenVINO uses fixed-length compilation buckets and returns normalized float32 embeddings; its padding ID is 1. The published minimum cosine agreement with the reference model is 0.9998 for the selected NPU variant, which measures numerical fidelity rather than search accuracy.

Independent model usage

from sentence_transformers import SentenceTransformer

model = SentenceTransformer("gety-ai/gety-embed-v0")
texts = ["Contract renewal terms", "Agreement extension conditions"]
vectors = model.encode(texts, normalize_embeddings=True)
print(vectors.shape)  # (2, 384)
print(model.similarity(vectors, vectors))

This example loads the public weights, not the Gety application's search engine. The exact production query formatting and batching policies are not established.

06 / Retrieval internals

Ranking, reranking and context pruning

Dense retrieval and lexical matching are documented, as is returning relevant excerpts to agents. These behaviors alone do not establish the algorithm responsible for ranking or shortening a passage.

ComponentEvidence status
Dense embedding encoderPublished: gety-embed-v0.
Lexical retrievalConfirmed functionality; scoring formula undisclosed.
BM25 / TF-IDFNot confirmed.
Learned sparse retrievalNot confirmed.
Rank fusion / RRFNot disclosed.
Cross-encoder rerankerNo verified model or implementation.
Neural context prunerNo verified model or implementation.
Passage extractionConfirmed behavior; segmentation and selection algorithms undisclosed.
ANN / HNSW / vector DBNot disclosed.

Why the distinction matters

An embedding encoder maps text to vectors for candidate retrieval. A reranker typically assigns query-dependent relevance scores to candidates. A context pruner removes irrelevant material inside retrieved passages. Returning a short excerpt could instead be implemented using lexical match windows, passage boundaries or scoring heuristics. Gety's documented excerpts should not be interpreted as proof of a separate neural pruning stage.

08 / Integration

Model Context Protocol (MCP)

Gety exposes a local authenticated Streamable HTTP server. Create an integration in Settings → AI Integrations → MCP and copy the generated configuration into the client. The default endpoint is shown below; use the actual generated credentials.

{
  "mcpServers": {
    "gety": {
      "type": "http",
      "url": "http://127.0.0.1:31226/mcp",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}
ToolPurpose
SearchReturn matching documents and excerpts, with identifiers and modification information.
GetDocRetrieve complete document content using connector_id and doc_id.
ListConnectorsDiscover sources and filesystem root paths for scoped searches.

An agent can discover sources, search a restricted corpus, evaluate results and fetch additional material when necessary. Gety does not itself implement the downstream reasoning loop or produce a synthesized answer.

09 / Programmatic access

REST API

Each configured integration has its own bearer token. The documented local base URL is http://127.0.0.1:31226.

curl -X POST 'http://127.0.0.1:31226/api/v1/search' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"query":"renewal clauses","limit":5,"semantic_search":true}'
RoutePurpose
POST /api/v1/searchSearch indexed corpus.
GET /api/v1/connectorsEnumerate sources.
GET /api/v1/connectors/{connector_id}/docs/{doc_id}Fetch extracted document content.
GET /api/v1/connectors/{connector_id}/docs/{doc_id}/fileDownload original bytes.

Error handling

Applications should distinguish authorization errors, invalid requests, absent resources, quota exhaustion, user-declined disclosure and internal failures. Consult the generated API documentation for the installed version before implementing production clients.

10 / Automation

Command-line interface

Enable CLI Commands in the AI Integrations settings, then reopen the terminal so the executable is available on PATH. The CLI supports scripting, structured output and interactive UI launch.

gety search "renewal terms" --limit 5 --json
gety search "invoice" --ext pdf --folder ~/Documents
gety search "exact identifier" --no-semantic-search
gety search "budget" --ui
gety doc CONNECTOR_ID DOC_ID --page-start 1 --page-end 3

Search options include pagination, file extensions, connector names, title/content/semantic match scope, folder and time restrictions, and result ordering. Page retrieval is limited to formats supporting pages. UI mode does not preserve every CLI filter: it applies the query and folder restriction.

Source: CLI reference.

11 / Extensibility

Connector ecosystem

Connectors ingest additional sources into the local corpus. They are distinct from AI integrations, which expose that corpus to consumers. Official connector listings include the following:

ConnectorIndexed material
LinearIssues and optional comments
NotionPages granted to the integration
ChromeLocal history and bookmarks
Codex / Claude CodeLocal session logs converted to Markdown
Feishu / LarkDocuments and chat history via authenticated local CLI

Development and distribution

Custom connectors can be installed from npm, public GitHub releases or a local directory containing a manifest. The developer documentation defines the connector contract and publishing conventions. Synchronization can be manual, interval-based or daily. Management includes configuration, restart, immediate sync, index rebuild and removal; npm installations support version switching.

Permissions

Connector installation reviews declared network, filesystem-read, environment and process-execution permissions. Sandboxed connectors are denied undeclared access, subject to documented baseline capabilities. Legacy or permissionless connectors may run without a sandbox; subprocesses can escape connector-level restrictions. Community packages deserve source and permission review before installation.

Sources: Connector overview, Build guide, Reference.

12 / Trust boundary

Privacy and security

Gety states that core file indexing, queries, OCR and semantic inference occur locally, with the index stored on the host. This claim is a vendor statement, not an independent network audit.

ControlEffect
Ask every timeRequire interactive approval of data disclosure to AI integrations.
Always allowPermit integration responses without per-request review.
Bearer credentialsAuthenticate API and MCP access.
LAN accessOptional access from trusted devices on a private network.

Local retrieval does not imply local downstream inference. An external AI provider may receive excerpts or full documents. The API also supports original-file download. Agents with separate filesystem permissions can bypass Gety's sharing controls.

Do not expose the service directly to the public internet. Limit network access, protect integration keys and review connector permissions. Encryption at rest, enterprise identity integration and detailed audit-log guarantees were not verified.

Sources: Privacy, FAQ — AI integration and remote access, API.

13 / Operations

Performance, maintenance and licensing

Gety advertises search results as fast as 0.01 seconds. This is a product claim rather than a reproducible latency benchmark; query complexity, index size, retrieval mode and hardware can affect performance. Initial AI indexing can take substantially longer than title indexing. No independent corpus-scale throughput, recall, nDCG or latency percentile measurements were performed for this report.

Free and Pro are documented as feature-equivalent, with monthly search and AI-integration quotas on Free and unlimited usage on Pro. One Pro license covers up to three personally owned devices. Consult the official site for current pricing and limits. The public embedding model's MIT terms are separate from application licensing.

Operational checks

When results are missing, inspect the indexing scope, file format rules, connector health, remaining indexing tasks and model downloads. When API or MCP access fails, check the running service, endpoint, token, integration settings and sharing prompts.

Sources: FAQ, Troubleshooting, File search.

14 / Technical assessment

What remains unverified

The published material establishes the product's functional contract and selected neural model artifacts, but does not provide a complete implementation specification. Important open questions include the database and ANN algorithm, lexical scoring formula, hybrid fusion policy, chunking and overlap, embedding batch strategy, OCR internals, dedicated reranking and pruning models, and exact desktop/backend framework.

These gaps are not evidence that a particular technology is absent. They are limits of public verification. This report does not include binary inspection, reverse engineering, runtime tracing or empirical testing. Architecture diagrams are explanatory reconstructions rather than vendor schematics.

Conclusion

Gety's defining characteristic is the separation of a persistent local retrieval corpus from the AI applications that consume it. Its small multilingual encoder and multiple optimized hardware exports are concrete evidence of an emphasis on efficient local inference. Its search, document extraction, extensible ingestion and disclosure controls form a useful retrieval interface; deeper claims about proprietary ranking and pruning require additional evidence.
